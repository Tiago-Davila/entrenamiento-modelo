REQUERIMIENTOS Y COMANDOS — EVA LSA64 v2
==========================================

Este archivo describe únicamente el pipeline de Eva para LSA64.
No corresponde al proyecto LSA-T.

CONTRATO DEL MODELO
-------------------

- 64 señas del catálogo oficial de LSA64.
- 40 cuadros por muestra.
- 168 coordenadas por cuadro:
    - mano izquierda: 21 x 3 = 63
    - mano derecha:   21 x 3 = 63
    - pose 11..24:    14 x 3 = 42
- Se descartan Pose 0..10 (cara) y Pose 25..32 (piernas).
- Los puntos no detectados se guardan como ceros.
- El resultado de esta versión no es compatible con el modelo Android
  anterior, que esperaba 40 x 201.

ESTRUCTURA NECESARIA
--------------------

Ejecutar los comandos desde:

    entrenamiento-modelo/lsa64

La carpeta debe contener:

    data/raw/all/                  videos LSA64 (.mp4)
    assets/holistic_landmarker.task modelo de MediaPipe
    catalogo_lsa64.json            catálogo oficial de 64 señas
    preprocess_tasks.py
    test_eva_contract.py
    train_keras_tflite.py

El archivo holistic_landmarker.task es un binario externo y está excluido
del repositorio por .gitignore. Hay que descargarlo y colocarlo manualmente
en assets/ antes de procesar los videos. Se debe usar el mismo archivo para
el procesamiento y para la futura aplicación Android.

REQUISITOS DEL SISTEMA
----------------------

- Windows 10/11, Linux o macOS.
- Python entre 3.9 y 3.13. Se recomienda Python 3.12.
- No usar Python 3.14 o superior: TensorFlow no tiene una wheel compatible.
- Espacio libre para los videos, los keypoints y los artefactos exportados.
- Para procesar todos los videos se recomienda una máquina con varios núcleos.
  El procesamiento de MediaPipe es principalmente CPU.

DEPENDENCIAS DE PYTHON
----------------------

Las versiones están declaradas en:

    lsa64/requirements.txt

Incluyen:

- mediapipe==0.10.33
- tensorflow-cpu>=2.17,<3.0
- numpy>=2.0,<3.0
- scikit-learn>=1.4,<2.0
- tqdm>=4.66,<5.0

INSTALACIÓN EN WINDOWS (POWERSHELL)
------------------------------------

1. Ubicarse en el proyecto:

    Set-Location -LiteralPath 'C:\ruta\entrenamiento-modelo\lsa64'

2. Crear el entorno con Python 3.12:

    py -3.12 --version
    py -3.12 -m venv .venv

3. Activarlo e instalar dependencias:

    Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
    & .\.venv\Scripts\Activate.ps1
    python -m pip install --upgrade pip setuptools wheel
    python -m pip install -r requirements.txt

4. Confirmar la instalación:

    python -c "import mediapipe as mp; from mediapipe.tasks.python import vision; import tensorflow as tf; print('MediaPipe:', mp.__version__); print('TensorFlow:', tf.__version__); print('HolisticLandmarker:', hasattr(vision, 'HolisticLandmarker'))"

INSTALACIÓN EN LINUX/MACOS
--------------------------

    cd /ruta/entrenamiento-modelo/lsa64
    python3.12 -m venv .venv
    source .venv/bin/activate
    python -m pip install --upgrade pip setuptools wheel
    python -m pip install -r requirements.txt

En Linux/macOS también se puede usar `uv venv --python 3.12 .venv` para
crear el entorno.

COMPROBACIONES ANTES DE PROCESAR
--------------------------------

Desde la carpeta lsa64 y con el entorno activado:

    python -c "from pathlib import Path; p=Path('assets/holistic_landmarker.task'); print('Modelo MediaPipe:', p.exists(), p)"
    python -c "from pathlib import Path; print('Videos:', len(list(Path('data/raw/all').glob('*.mp4'))))"
    python test_eva_contract.py

La primera comprobación debe mostrar `True`, la segunda debe mostrar la
cantidad de videos disponibles y el test debe terminar en `OK`.

REEXTRAER LOS KEYPOINTS (OBLIGATORIO PARA EVA v2)
--------------------------------------------------

Los keypoints antiguos de 40 x 201 no sirven para esta versión. Hay que
procesar nuevamente los videos originales:

    python preprocess_tasks.py --videos data/raw/all --out data/processed --model assets/holistic_landmarker.task

El resultado esperado es:

    data/processed/X.npy
    data/processed/y.npy
    data/processed/subjects.npy
    data/processed/reps.npy
    data/processed/meta.json

`X.npy` debe tener forma `(muestras, 40, 168)`. Verificarlo con:

    python -c "import numpy as np; x=np.load('data/processed/X.npy'); print(x.shape); assert x.ndim == 3 and x.shape[1:] == (40,168)"

No utilizar un `X.npy` generado por el contrato anterior de 201 coordenadas.

AUMENTACIÓN Y ENTRENAMIENTO
---------------------------

El entrenamiento aplica aumentación únicamente sobre el split de train.
El valor recomendado deja las muestras originales y agrega dos copias
aumentadas por muestra:

    python train_keras_tflite.py --data data/processed --out exports --epochs 120 --augment-factor 2

Para una línea base sin aumentación:

    python train_keras_tflite.py --data data/processed --out exports --epochs 120 --augment-factor 0

Antes de un entrenamiento largo se puede verificar que el script y la
conversión estén disponibles:

    python train_keras_tflite.py --help

ARTEFACTOS DE UNA CORRIDA COMPLETA
----------------------------------

La carpeta `exports/` debe contener el conjunto generado por la misma corrida:

    modelo_lsa.tflite
    catalogo_senas.json
    lsa-manifest.json
    fixture_android.json
    metricas.json

El modelo, el catálogo, el manifiesto y el fixture son una unidad. No copiar
uno de ellos por separado a Android.

VALIDACIONES POSTERIORES
------------------------

1. Revisar que `X.npy` sea `(muestras, 40, 168)`.
2. Revisar que el entrenamiento termine sin errores de conversión TFLite.
3. Revisar `metricas.json` antes de integrar el modelo.
4. Verificar que el manifiesto registre el hash del modelo y del catálogo.
5. No instalar todavía estos artefactos en la aplicación actual: Android
   todavía debe actualizar su contrato de 201 a 168 coordenadas.
